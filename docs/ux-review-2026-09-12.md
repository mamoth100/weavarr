# UX review findings, 2026-09-12

Second pass, done live against http://10.0.0.254:6767 at desktop and 375px
phone width, with the component code open beside it. The August review
(`ux-review-2026-08-14.md`) fixed the mobile-breaking items; this one is
about ease of use for someone who did not build the app, prompted by the
first outside install today. Checkboxes so it works as a punch list.
Nothing here is built yet.

## Getting started (the first ten minutes)

- [x] **Settings has no starting point.** A fresh install opens Settings on
      Connections with four collapsed groups and a note about secret fields.
      Nothing says what is needed for what. Discover already works with no
      setup (TMDB token is bundled), requesting needs Sonarr or Radarr, the
      Watch page needs Plex or Jellyfin, and the downloader is optional.
      Fix: a short setup card at the top of Settings with three rows and a
      tick per row (Sonarr/Radarr, Plex/Jellyfin, downloader), each linking
      to its group already expanded. Auto-expand any group that is not
      configured yet. Small effort, biggest payoff for new users.
- [x] **The restart requirement is invisible.** "Takes effect after a
      restart" only appears inside per-field tooltips. After Save nothing
      tells you the new values are not live, so a new user tests Jellyfin,
      sees green, then wonders why Watch is empty. Fix: after saving any
      key that needs a restart, show "Saved. Restart to apply." inline with
      the Restart App button highlighted, and clear it after the restart.
- [x] **Connection state is hidden until you expand a group.** The collapsed
      headers (Metadata, Media Management, Downloaders, Media Players) give
      no hint which services are configured or failing. Fix: a coloured dot
      per service on the header (green connected, grey not configured, red
      last test failed) using the last Test result.

## Headings and navigation

- [x] **Page titles are taglines.** "Watch - what's missing, downloaded and
      unwatched, movies and shows", "Download status - Downloader, Sonarr,
      Radarr", "Library - movies and shows, all in one place", "Calendar -
      what's airing and releasing, across movies and shows", "Search
      anything - movies, TV, any genre", plus the Radarr and Sonarr library
      pages. On a phone the Watch title wraps to three lines and pushes the
      content down a full screen. They also break the no-dash rule. Fix:
      one-word H1 (Watch, Status, Library, Calendar, Search) with the
      explanation as a small muted subtitle, or drop the explanation.
- [x] **"Back" on every top-level page.** Pages reached from the sidebar
      (Watch, Status, Library, Calendar, Requests, Watched, Not interested,
      Settings) all carry a top-right Back that goes to browser history,
      which is wherever you came from. It reads as "back to what?". Keep it
      on detail pages only, where it means something.
- [x] **Two search boxes with different scopes.** Genre pages have "Search
      documentaries…" while the sidebar Search is everything. Typing a show
      name into the Documentaries box returns nothing and there is no hint
      why. Fix: when a genre search finds nothing, show "Nothing in
      Documentaries. Search everything for X" as a link.

## Browsing

- [x] **Card actions cover the poster on phones.** The August fix made the
      three actions always visible on touch, but they are three full-width
      pills stacked over the top 60% of the artwork, so the poster is barely
      visible while browsing. Fix: one compact button per card that opens a
      small action sheet, or a slim icon row under the poster.
- [x] **Coming Soon leads with junk.** Sorted by release date, the top rows
      are whatever obscure titles release today; half the first ten cards
      are "No Poster" placeholders. Fix: hide items with no poster or below
      a popularity floor, and sort by popularity within a date. A "This
      week" and "Later" split would help too.
- [x] **Detail page on a phone is a wall before the title.** Full-width
      hero, then a Back link floating over it, then a full-width poster
      block, and only then the title and actions, roughly one and a half
      screens down. Fix: on small screens put a small poster beside the
      title under a shorter hero (the Seerr layout), actions directly under.
      Also the detail poster `Image` has no `sizes` attribute, so it asks
      the server for a full-viewport-width render of a 342px source.
- [x] **Detail actions all look the same.** Mark watched, Not interested,
      Get more and Delete from Sonarr sit in one row at equal weight. Delete
      does confirm ("Really delete?"), which is good, but it should read as
      the dangerous one: outlined red, separated to the right.

## Watch, Status and cleanup

- [x] **Recently Watched shows things nobody watched.** The Status page
      lists Real Housewives of Beverly Hills episodes as "Marked watched
      manually, watched 2d ago". They were marked on Plex months ago; the
      watched-sync relayed them to Jellyfin recently, which gave them a
      fresh timestamp. To a user this looks like a bug. Fix: when relaying
      a mark, carry the source server's original date instead of "now",
      and add a small "why is this here" tooltip on the reason label.
- [x] **Row actions are hidden in dropdowns.** (Review overreach: "+N more" was already an expand toggle. Shipped as clearer labels, "Mark watched" and "Delete episodes".) Watch rows use "Watched ▾"
      and "Delete ▾" whose options only appear when opened, and the episode
      list truncates to "S01E02, S01E03 … +2 more unwatched". On a phone the
      row is cramped. Fix: one primary action per row and a "…" overflow,
      and make "+2 more" expand in place.
- [x] **Stat tiles look clickable but do nothing.** (Wrong: they already jump to their section. No change.) "12 TV shows, 2 movies,
      3 movies not found, 8 recently watched" at the top of Watch. Make each
      jump to its section, or render them as plain text so they do not
      invite a tap.

## Requests and Library

- [x] **Requests intro is a paragraph.** Cut to one sentence; the retention
      detail can live in a tooltip.
- [x] **Repeat requests stack up.** The same show requested twice shows as
      two identical rows. Collapse to the latest with a "x2" count.
- [x] **"Requested 9/12/2026 - Seasons" says nothing.** Show which seasons
      ("Seasons 1, 2" or "All seasons") and use the no-dash form.
- [x] **Library rows do not show progress.** Many rows read "No files" plus
      "Continuing" with no poster, so a show that is mid-download looks the
      same as one Sonarr never found anything for. Fix: an episodes-on-disk
      count ("3 of 10"), a downloading state, and make the row itself open
      the detail page instead of a separate Details button.

## Settings on a phone

- [x] **Tabs overflow with no hint.** Connections, App Config,
      Notifications, then "Me…" cut off at the right edge with no scroll
      cue. Fix: let the chips wrap, or use a select below `sm`.

## Already good, keep it

- Discover works out of the box because the TMDB token is bundled.
- Request modal: season picker with owned items locked, "All seasons" at
  the top, future-episodes toggle explained in place.
- Delete asks "Really delete?" before doing anything.
- Calendar legend and month grid; mobile drawer with page title in the bar.
- Sidebar "Update available" only appears when there is something to do.

## Suggested order

1. Setup card in Settings (first ten minutes).
2. "Saved. Restart to apply." after save.
3. Short page titles.
4. Card actions on phones.
5. Recently Watched carrying the real watched date.
6. Coming Soon filtering.
7. Connection dots on collapsed groups.
8. Genre search fallback to global search.
9. Everything else in listed order.

## Status

All items shipped 2026-09-12, same day as the review, in four commits:
Settings (setup card, restart notice, dots, wrapping tabs), headings and
navigation (short titles with subtitles, Back only on standalone pages,
genre search fallback), browsing (touch card menu, Coming Soon filter,
phone detail layout, red delete), and Watch/Requests/Library (earliest
watched date across servers with a tooltip on manual marks, one-line
Requests intro with collapsed repeats and clearer season labels, live
download state on Library rows). Two Watch items were already true before
the review and are marked as such above.

Follow-up the same evening: the Recently Watched fix needed more than the
history merge, because Plex's real dates for those rows sat outside the
window the app reads. The sync now stamps relayed Jellyfin marks with
Plex's original date (`datePlayed`), the seven Housewives rows were
repaired on Jellyfin with their Plex dates, and one orphaned relay (Vice
Principals, unmarked on Plex since) was cleared on Jellyfin.
